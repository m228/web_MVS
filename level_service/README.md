# Сервис уровня — YOLO-модель → контуры (декантатор)

Отдельный процесс рядом с `web_MVS` (как `cv_service` и `motion_service`). Держит обученную YOLO-модель и по кадру отдаёт контуры
найденных объектов. Что из найденного считать жидкостью и как из этого получить уровень, решает не он, а `motion_service`
(вкладка **«Уровень»** панели «КЗ» в мультипросмотре): зоны-стёкла рисует человек на кадре, уровень = доля площади зоны,
залитая маской жидкости, Total = (нижнее + верхнее) · 50 %, в ПЛК — ×10 (54,3 % → 543). Подробнее — `motion_service/README.md`, раздел «Уровень жидкости».

Сервис про «жидкость» ничего не знает: он отдаёт объекты **всех классов** модели, поэтому подойдёт любая seg- или detect-модель
(`.pt`, `.onnx`) — меняется только имя класса в параметрах вкладки («Класс жидкости»).

## Установка (один раз)

1. Python 3.10+ в PATH.
2. **`setup.bat`** — создаст `.venv`, поставит OpenCV, FastAPI, ultralytics (8.4+, нужен для YOLO26) и torch. По умолчанию — **процессорная** сборка
   (видеокарта не нужна: модель 26x даёт ~0,8 с на кадр, опроса раз в 2 с хватает). `setup.bat gpu` — заменит torch на CUDA-сборку (cu124).
   Системный прокси подхватит сам. На голой винде нужен Microsoft Visual C++ Redistributable x64 (иначе torch падает с `c10.dll … WinError 1114`).
3. Модель загружается **из браузера**: вкладка «Уровень» → «Загрузить модель…» (файл `.pt` из `data\` рядом с LVLDec.exe, например `26x_detection.pt`).
   Сервис сохранит её в `model\` и подхватит сразу, без перезапуска. Можно и руками: положить файл в `model\best.pt`.

## Запуск

Руками не нужно: web_MVS сам поднимает сервис при старте (без окна, вывод — `level_service\service.log`) и раз в минуту проверяет `/health`;
упал — поднимает снова. Адрес `127.0.0.1:8770` (порт 8769 занят приёмником мониторинга). Отключить автозапуск:
`plate_config.json` → `"services": {"level": {"autostart": false}}`, тогда — `run.bat`. Адрес меняется в `plate_config.json` →
`"level": {"service_url": "http://127.0.0.1:8770"}` (и в группе-уровне камеры, поле `service_url`, если сервис на другом компьютере).

**Сайдкар помнит последнюю загруженную модель** (`model\last_model.json`): после перезапуска берёт её, а не `best.pt`.
`LEVEL_MODEL` / `model\best.pt` из `run.bat` — только запасной вариант. Сбросить память — удалить `model\last_model.json`.

## Переменные окружения

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `LEVEL_HOST` / `LEVEL_PORT` | адрес / порт | 127.0.0.1 / 8770 |
| `LEVEL_MODEL` | запасная модель, если запомненной нет | — |
| `LEVEL_DEVICE` | `cpu` / `cuda:0`; пусто — CUDA, если есть, иначе процессор | авто |

## Геометрия масок (`geometry`)

Сеть считает маску в «письмовом» размере (letterbox: для кадра 1920×1080 при размере входа 640 — 640×384 с полями по 12 строк сверху и снизу).
- **`lvldec`** (по умолчанию) — как в LVLDec.exe: маска растягивается на весь кадр вместе с полями. Края кадра при этом «съезжают» к центру (до ~30 px на 1080p).
  Заводские калибровки («полное верхнее 84 %») подобраны именно под это, поэтому цифры совпадают с прежними.
- **`exact`** — поля вырезаются, маска ложится на кадр без растяжения. Честнее, но «Полное» нужно подобрать заново.

## API

| | |
|---|---|
| `GET /health` | жив, версия, текущая модель, `load_error` (почему не загрузилась запомненная) |
| `GET /model`, `GET /models` | метаданные модели (имя, классы, размер входа, устройство); файлы в `model\` и текущая |
| `POST /model/upload?name=x.pt` | залить `.pt` / `.onnx` (сырые байты), сохранить в `model\` и загрузить; битая модель старую не заменяет |
| `POST /model/load` `{"path": …}` | загрузить файл с диска сервиса |
| `POST /infer?conf=&iou=&imgsz=&max_det=&geometry=` | тело — кадр (jpg/png) → `{image, geometry, count, objects:[{cls, name, conf, bbox, polygons}], timing:{ms}, model}`; нет модели → 409 |

`polygons` — внешние контуры в пикселях **присланного кадра**. У detect-модели (без масок) вместо контура — прямоугольник рамки.
